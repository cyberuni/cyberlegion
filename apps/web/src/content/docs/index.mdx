## Two ways in

<CardGrid>
  <Card title="Ask the Legate" icon="pencil">
    The agent plugin. Say what you want in plain language and it works out how to reach the target: a warm peer in its own pane, a cold one-shot subagent, or the work done in-session.
    [View skills →](/cyberlegion/skills/)
  </Card>
  <Card title="Drive the CLI" icon="seti:shell">
    `cyberlegion` spawns sessions, sends and reads mail, and reports which multiplexer is live. Reach for it when you already know the command, or when you are scripting.
    [CLI reference →](/cyberlegion/cli/)
  </Card>
</CardGrid>

## What you get

<CardGrid>
  <Card title="Nothing to keep alive" icon="rocket">
    No server, no port, no daemon. State is files under a shared hub root, and each harness's own session-start hook delivers the mail.
  </Card>
  <Card title="One Legion, every harness" icon="laptop">
    Claude Code, Cursor, and Codex sessions address each other the same way, so a mixed set of tools behaves like one team.
  </Card>
  <Card title="Addressable units" icon="random">
    An `agent` is a definition, a `unit` is a running instance with its own mailbox, a `pane` is where it lives.
    [The spine →](/cyberlegion/concepts/spine/)
  </Card>
  <Card title="Output agents can read" icon="document">
    Token-efficient TOON by default, `--format json` as the escape hatch, structured errors, and definitive empty states.
  </Card>
</CardGrid>
